## Add

```sh
npx @ava-ui/apogee add tabs
```

No Apogee dependencies. Ships one scoped JS island (progressive enhancement).

## Usage

```astro
---
import Tabs from '@/components/apogee/Tabs/Tabs.astro'
---
<Tabs tabs={['Account', 'Password']}>
  <div slot="panel-0">Account settings…</div>
  <div slot="panel-1">Password settings…</div>
</Tabs>
```

Labels come from the `tabs` array; each panel goes in a matching `panel-<i>` slot
(0-indexed, same order as the labels).

## Anatomy

- **Tablist** — the row of `role="tab"` buttons (the labels).
- **Tabpanel** — one `role="tabpanel"` per tab; the first is shown, the rest are
  `hidden` until selected.

## API

`@composable` — exposed to Content Editors in AVA. Any other attribute passes
through to the root `<div>`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `tabs` | `(string \| { label, value?, href?, disabled?, icon?, badge? })[]` | — | Tabs in order. A string is a label; an object adds a `value` (panel slot name and event value, defaults to the index), an `href` (renders a link, no panel), `disabled`, an `icon` (Lucide component) or a `badge` (count or short text, shown from `md`). |
| `value` | `string` | first enabled tab | Value of the tab shown first. |
| `variant` | `'bordered' \| 'borderless' \| 'pills' \| 'pills-raised' \| 'primary'` | `'bordered'` | Underline with a list border, underline alone, chip, chip in a raised tray, or a primary-tinted chip. |
| `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` | `vertical` stacks the list beside the panels; Up and Down move between tabs; underline variants draw on the start edge. |
| `fullWidth` | `boolean` | `false` | Tabs share the list width equally (horizontal only). |
| `activation` | `'automatic' \| 'manual'` | `'automatic'` | `manual`: arrows move focus, Enter or Space selects. Use it when a panel is expensive to show. |
| `size` | `'small' \| 'medium' \| 'large'` | `'medium'` | Tab height and text size. |
| `class` | `string` | — | Extra classes on the root, merged last. |

Panels are slots named `panel-<value>`: `panel-0`, `panel-1`, … for string
tabs, `panel-billing` for `{ value: 'billing' }`.

## Overflow

The list scrolls, the hidden edge fades, and the selected tab is scrolled into
view.

<Preview code={`<Tabs class="max-w-sm" tabs={['Overview', 'Analytics', 'Reports', 'Notifications', 'Integrations', 'Billing', 'Security', 'Members', 'Audit log', 'Exports']}>
  <div slot="panel-0">…</div>
  …
</Tabs>`} block>
  <div data-apogee-tabs="overflow">
    <Tabs class="max-w-sm" tabs={['Overview', 'Analytics', 'Reports', 'Notifications', 'Integrations', 'Billing', 'Security', 'Members', 'Audit log', 'Exports']}>
      {['Overview', 'Analytics', 'Reports', 'Notifications', 'Integrations', 'Billing', 'Security', 'Members', 'Audit log', 'Exports'].map((label, i) => (
        <div slot={`panel-${i}`}>{label} panel.</div>
      ))}
    </Tabs>
  </div>
</Preview>

The tab that starts active is not scrolled into view on load. Put it among the first visible tabs, or call `scrollIntoView` on it.

## States

- **Selected** — the active tab has an accent underline and `aria-selected="true"`;
  its panel is visible.
- **Hover / focus** — inactive tabs lighten on hover; keyboard focus shows a visible
  ring (`focus-visible:outline-focus`).
- **Disabled** — dimmed, not clickable, skipped by the arrows.
- **No JS** — every panel is shown (the `no-js:block` fallback).

## Events

The root dispatches `apogee:tabs-change` (`detail: { index, value }`, bubbling) whenever a tab is selected.

## Accessibility

| Key | Action |
|---|---|
| `Tab` | Moves focus into the tablist (one stop), then to the active panel. |
| `←` `→` | Move between tabs and select, wrapping at the ends; swapped under `dir="rtl"`. |
| `↑` `↓` | With `orientation="vertical"`, move between tabs instead of `←` `→`. |
| `Home` `End` | First / last tab. |
| `Enter` `Space` | With `activation="manual"`, select the focused tab (arrows then only move focus). |

- Full **WAI-ARIA tabs pattern**: `role="tablist"` / `role="tab"` /
  `role="tabpanel"`, wired with `aria-selected`, `aria-controls`, and
  `aria-labelledby`.
- Each panel is focusable (`tabindex="0"`), so `Tab` from the active tab lands
  on its panel before moving on.
- **Focus** — a visible `focus-visible` ring on each tab.
- **No JS** — panels are never trapped: with scripts off every panel renders, so
  the content is fully reachable.
- The panel enter animation respects `prefers-reduced-motion`.

## Tokens

| Token | Used for |
|---|---|
| `--border-neutral` | Tablist bottom rule + inactive tab border |
| `--border-primary` | Selected tab underline |
| `--foreground-neutral` / `--foreground-neutral-faded` | Active vs. inactive label colour |
| `--outline-color-focus` | Focus ring |
| `--duration-medium` / `--ease-standard` | Panel enter animation |

## Do / Don't

- **Do** keep labels to one or two words so the tablist stays scannable.
- **Do** use tabs for parallel, peer-level content — not for a sequence (use
  `Steps`) or for progressive disclosure of one thing (use `Accordion`).
- **Don't** put a form that must submit as a whole across multiple tabs — a user
  can't see all fields at once.
- **Don't** hide critical content behind a non-default tab if a no-JS user must
  act on it immediately (though it stays reachable, it's below the fold).

## Content

- Labels are nouns, sentence case, one or two words ("Account", "Billing history").
- No ending punctuation. Don't number them — the order is the sequence.
