## Add

```sh
npx @ava-ui/apogee add section
```

Pulls in `Container`.

## Usage

```astro
---
import Section from '@/components/apogee/Section/Section.astro'
---
<Section space="lg">
  <h2>About us</h2>
  <p>…</p>
</Section>
```

## Anatomy

- **Content** (default slot) — wrapped in a `Container` unless
  `container={false}`.
- **`slot="background"`** — renders full-bleed behind the content
  (`absolute inset-0 -z-10`), for a background image/gradient/pattern that
  should ignore the `Container`'s width.

## API

`@composable` — exposed to Content Editors in AVA. Any other attribute
passes through to the root element.

| Prop | Type | Default | Description |
|---|---|---|---|
| `as` | `string` | `'section'` | Element/tag to render. |
| `theme` | `'inherit' \| 'light' \| 'dark'` | `'inherit'` | Flips design tokens for this section and everything inside it (sets `data-theme`). |
| `space` | `'none' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'lg'` | Vertical padding. |
| `containerSize` | `'sm' \| 'md' \| 'lg' \| 'xl' \| 'full'` | `'lg'` | Width of the inner `Container`. |
| `container` | `boolean` | `true` | Set `false` to skip the inner `Container` — content spans full width. |
| `class` | `string` | — | Extra classes, merged last. |

## Accessibility

- `as` picks the rendered element — choose a real landmark (`section`,
  `nav`, `aside`, …) rather than leaving every Section a generic
  `<section>` when a page has several; give repeated landmarks of the same
  type an accessible name (`aria-label` / `aria-labelledby`).
- `theme` only flips CSS custom properties (`data-theme`) — it carries no
  ARIA implications.
- Native semantics otherwise — no extra ARIA needed.

## Tokens

| Token | Used for |
|---|---|
| `--background` | Section fill, only when `theme` isn't `inherit` |
| `--foreground` | Section text color, only when `theme` isn't `inherit` |

A themed Section flips the token context for its whole subtree — every
component nested inside also reads its own tokens from that context; see
each component's own Tokens table.

## Do / Don't

Layout primitive — no content or misuse surface of its own; guidance lives
on the components placed inside it.

## Content

Layout primitive — no text of its own.
