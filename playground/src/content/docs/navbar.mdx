## Add

```sh
npx @ava-ui/apogee add navbar
```

No Apogee dependencies (compose the link slot with `NavLink` for
free active-state styling). Bring `@lucide/astro` for the mobile menu icon.
Ships one scoped JS island (progressive enhancement).

## Usage

```astro
---
import Navbar from '@/components/apogee/Navbar/Navbar.astro'
import NavLink from '@/components/apogee/NavLink/NavLink.astro'
---
<Navbar>
  <a slot="brand" href="/">Acme</a>
  <NavLink href="/docs">Docs</NavLink>
  <NavLink href="/pricing">Pricing</NavLink>
</Navbar>
```

## Anatomy

- **`brand` slot** — logo or wordmark, leftmost.
- **default slot** — nav links. Inline row on desktop (≥768px); a stacked
  panel below the header on mobile, hidden until the toggle opens it.
- **`actions` slot** — right-aligned buttons/controls. Hidden entirely
  below 768px (`hidden md:flex`) — it does **not** move into the mobile
  panel, so don't put anything mobile users need only there.
- **mobile toggle** — a hamburger button (`md:hidden`), controls the links
  panel via `aria-controls` / `aria-expanded`.

## API

`@composable` — exposed to Content Editors in AVA. Any other attribute
passes through to the root `<header>` (`...rest`).

| Prop | Type | Default | Description |
|---|---|---|---|
| `class` | `string` | — | Extra classes on the root `<header>`, merged last. |

## States

- **Collapsed** (mobile, default) — the links panel is hidden below 768px
  until toggled open.
- **Open** (mobile) — `data-open="true"` on the panel; toggle's
  `aria-expanded="true"`.
- **Desktop** (≥768px) — links show inline always; the toggle and its
  panel logic don't apply.
- **No JS** — see the JsNote above; the toggle is hidden and the links
  panel stays expanded.

## Accessibility

- `<header>` / `<nav>` landmarks wrap the content.
- The toggle is a real `<button>` with `aria-controls` pointing at the
  panel's id and `aria-expanded` synced by JS; `aria-label="Toggle menu"`
  since it's icon-only.
- **Keyboard** — the toggle is a native button (`Enter` / `Space`
  activates); links are native `<a>` elements in DOM order.
- **No JS** — the toggle carries `no-js:hidden` and the links panel
  carries `no-js:flex`, so below 768px the toggle disappears and the
  links render expanded — never a dead control, and the nav stays fully
  reachable. Desktop is unaffected — links and actions render inline via
  CSS regardless of JS.

## Tokens

| Token | Used for |
|---|---|
| `--border` | Header bottom border / mobile panel border |
| `--background` | Header and mobile panel background |
| `--foreground` | Toggle icon colour |
| `--muted` | Toggle hover background |
| `--ring` | Toggle focus ring |

## Do / Don't

- **Do** put the primary call-to-action in `actions`, not buried in the
  link list.
- **Do** pair the default slot with `NavLink` so the current page gets its
  active state for free.
- **Don't** assume `actions` content survives on mobile — it's hidden
  below 768px, not moved into the collapsible panel; duplicate anything
  essential into the links slot if mobile users need it.
- **Don't** assume the toggle is visible without JS — it's `no-js:hidden`
  by design; the links panel takes over as the fallback instead.

## Content

- Keep top-level link labels to one or two words; put anything longer in
  a dropdown or menu component instead.
- Give the `brand` slot real link text, or an `aria-label` / `alt` if it's
  a logo image only.
