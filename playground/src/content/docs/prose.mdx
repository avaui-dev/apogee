## Add

```sh
npx @ava-ui/apogee add prose
```

No Apogee component dependencies, no icons. Zero JS — a global,
`.apogee-prose`-scoped CSS layer.

## Usage

```astro
---
import Prose from '@/components/apogee/Prose/Prose.astro'
---
<Prose set:html={article.body} />
```

## API

`@composable` — exposed to Content Editors in AVA. Accepts any other attribute
(e.g. `set:html`, `id`), which passes through to the wrapper `<div>`.

| Prop | Type | Default | Description |
|---|---|---|---|
| `class` | `string` | — | Extra classes on the wrapper, merged last. |

## Examples

Trusted/sanitized CMS or markdown HTML:

```astro
<Prose set:html={renderedMarkdown} />
```

Authored inline as children instead:

```astro
<Prose>
  <h2>Release notes</h2>
  <p>What changed in this version.</p>
</Prose>
```

## Accessibility

- Native semantics, no extra ARIA needed — Prose is a CSS layer over your own
  markup; semantics come entirely from the HTML you put inside (or the CMS HTML
  you render).
- Using `set:html`: sanitize the source yourself — Prose only styles, it never
  sanitizes.

## Tokens

| Token | Used for |
|---|---|
| `--foreground` | Body + heading text |
| `--accent` / `--accent-hover` | Link colour / hover |
| `--muted-foreground` | List marker colour, blockquote text |
| `--border` | Blockquote rule, `<hr>` |
| `--muted` | Inline `code` and `pre` background |
| `--radius-sm` | Inline `code` corner radius |
| `--radius-md` | `pre` and `img` corner radius |

## Do / Don't

- **Do** use it for any block of HTML you don't style element by element — CMS
  output, rendered markdown, long-form copy.
- **Do** sanitize untrusted HTML before `set:html` — Prose doesn't clean input,
  it only styles it.
- **Don't** reach for Prose to style one isolated element (a lone `<p>` or
  `<a>`) — style it directly instead.
- **Don't** nest interactive app UI (buttons, forms) inside — it's a typography
  layer, not a layout system.

## Content

- No wording rules of its own — copy follows whatever produced it (CMS,
  markdown, hand-authored). Keep headings short enough that the built-in
  `text-wrap: balance` reads well.
