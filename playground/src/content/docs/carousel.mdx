## Add

```sh
npx @ava-ui/apogee add carousel
```

No Apogee dependencies. Uses `@lucide/astro` for the prev/next chevrons.

## Usage

```astro
---

---
<Carousel itemWidth="16rem" dots>
  <div>Slide 1</div>
  <div>Slide 2</div>
  <div>Slide 3</div>
</Carousel>
```

## Anatomy

- **Track** — the scrollable, `scroll-snap-x` element holding your slides (the
  default slot). Always present, always usable, never gated behind JS.
- **Prev / Next buttons** (optional, `controls`) — absolutely positioned arrow
  buttons that scroll the track. A progressive-enhancement island:
  `no-js:hidden`.
- **Dots** (optional, `dots`) — one pagination dot per top-level slide, in a
  `role="group"`. Also an island: `no-js:hidden`. Dot count is derived by
  parsing the slotted markup at build time, not passed as a prop.

## API

`@composable` — exposed to Content Editors in AVA. Any other native `<div>`
attribute passes through to the root.

| Prop | Type | Default | Description |
|---|---|---|---|
| `controls` | `boolean` | `true` | Show the prev/next arrow buttons. |
| `dots` | `boolean` | `false` | Show clickable pagination dots (one per slide). |
| `align` | `'start' \| 'center'` | `'start'` | Snap edge of each slide. |
| `itemWidth` | `string` | — | Fixed width applied to every slide (e.g. `"16rem"`). Omit to size each slide yourself. |
| `autoplay` | `boolean` | `false` | Auto-advance. Pauses on hover/focus; never runs under `prefers-reduced-motion`. |
| `interval` | `number` | `4000` | Autoplay delay in ms. |
| `loop` | `boolean` | `false` | With autoplay, jump back to the start after the last slide. |
| `label` | `string` | `'Carousel'` | Accessible name of the carousel region. |
| `class` | `string` | — | Extra classes on the root, merged last. |

Slides go in the default slot, one top-level element per slide. Give each
slide its own width, or set `itemWidth` for uniform slides.

## States

- **Hover / focus** — arrow buttons and dots lighten/highlight on hover; a
  visible `focus-visible` ring (`--border-primary`) on keyboard focus.
- **Active dot** — the dot for the in-view slide gets `aria-current="true"`
  and an accent fill; tracked live via `IntersectionObserver` as the user
  scrolls (not just on click).
- **No JS** — arrows and dots are hidden (`no-js:hidden`); the track itself
  has no disabled state, it's always scrollable.

## Accessibility

- The track is a `region` with `aria-roledescription="carousel"`; each slide gets `aria-roledescription="slide"` and an `n of N` label.
- Arrows are 44px targets and hide at the first and last slide; the track scrolls by touch and, once focused, by arrow keys.
- The root dispatches `apogee:carousel-change` (`detail: { index }`) when the visible slide changes.

- **Keyboard** — the track has `tabindex="0"`: once focused, arrow keys scroll
  it natively (browser default for a scrollable region) — works with or
  without JS. `Tab` also reaches the Prev/Next buttons and each dot when
  present.
- Prev/Next buttons carry `aria-label="Previous"` / `aria-label="Next"`.
- Dots sit in a `role="group"` (`aria-label="Slides"`); each dot button has
  `aria-label="Go to slide N"` and `aria-current` reflecting the in-view slide.
- **No JS** — arrows and dots are hidden entirely (`no-js:hidden`), not shown
  disabled; nothing is lost, since the track scrolls by touch, trackpad, or
  focused arrow keys regardless.
- **RTL** — under `dir="rtl"` the track runs right-to-left; Next scrolls
  toward the start edge and the arrow icons flip, so the controls read
  correctly.
- Autoplay pauses on hover and on focus, and never starts under
  `prefers-reduced-motion: reduce`.

| `--border-primary` | Focus ring on arrows and dots |

## Do / Don't

- **Do** set `itemWidth` for uniform slides, or size each slide yourself for a mixed-width track.
- **Do** enable `dots` when there are few enough slides that a dot-per-slide stays scannable.
- **Don't** put content a user *must* see behind autoplay — they may miss a slide, and no-JS users never get it advancing at all.
- **Don't** rely on the carousel as the only path to its content if any slide holds critical, unique information — link to it elsewhere too.

## Content

- Keep slide content self-contained — a user may land on any slide first (via a dot or a scroll), not always the first one.
- Alt text on slide images should describe the image, not "slide 1 of 4" — the dots already convey position.
