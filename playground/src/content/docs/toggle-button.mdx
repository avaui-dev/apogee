## Add

```sh
npx @ava-ui/apogee add toggle-button
```

No Apogee dependencies. Ships one scoped JS island (progressive enhancement).

## Usage

```astro
---

```

## API

`@composable` — exposed to Content Editors in AVA. Any other native `<button>`
attribute (e.g. `disabled`) passes through.

| Prop | Type | Default | Description |
|---|---|---|---|
| `pressed` | `boolean` | `false` | Initial (and, in `manual` mode, current) pressed state. |
| `manual` | `boolean` | `false` | Don't self-toggle on click — a parent (e.g. a rich-text toolbar) owns `aria-pressed`. |
| `value` | `string` | — | Identity inside a group and the submitted value. |
| `name` | `string` | — | With `value`, a hidden input submits the value while pressed, with or without JS. |
| `color` | `'primary' \| 'neutral' \| 'critical' \| 'positive' \| 'warning'` | `'neutral'` | Resting hue. |
| `variant` | `'solid' \| 'faded' \| 'outline' \| 'ghost'` | `'ghost'` | Resting fill style (the Button tables). |
| `size` | `'small' \| 'medium' \| 'large' \| 'xlarge'` | `'medium'` | Height scale, same as Button. |
| `selectedColor` | `'primary' \| 'neutral' \| 'critical' \| 'positive' \| 'warning'` | `'neutral'` | Pressed hue. |
| `selectedVariant` | `'solid' \| 'faded'` | `'faded'` | Pressed fill style. |
| `rounded` | `boolean` | `false` | Fully round ends. |
| `iconOnly` | `boolean` | `false` | Square button for a lone icon; give it an `aria-label`. |
| `aria-label` | `string` | — | Label when the button is icon-only. |
| `class` | `string` | — | Extra classes, merged last. |

- **Pressed** — the `selectedVariant` × `selectedColor` fill (default a faded
  neutral).
- **Hover** — the resting variant's hover fill; pressed buttons use the
  selected fill's highlighted step.
- **Focus** — visible `focus-visible` ring (`--border-primary`).
- **Disabled** — dimmed, not interactive.
- **No JS** — click does nothing; the button stays at its initial `pressed` value.

## In a form

A hidden input submits `value` under `name` while pressed; nothing is submitted
when unpressed, and a button with `name` but no `value` never submits.

## Events

Each button dispatches `apogee:toggle-change` (`detail: { pressed, value }`, bubbling) after it toggles.

## Accessibility

- Real `<button type="button">` with `aria-pressed` — the native two-state
  pattern, full keyboard support for free.
- **Keyboard** — `Tab` to focus, `Enter` / `Space` to toggle (native button
  behavior).
- **Focus** — a visible `focus-visible` ring.
- Icon-only usage (no visible text) always needs `aria-label`.
- **No JS** — the button is present and focusable but inert; `aria-pressed`
  never changes. Don't ship an icon-only, JS-dependent toggle as the only way
  to reach a piece of functionality.

| `--foreground-neutral-faded` / `--foreground-neutral` | Unpressed vs. pressed label color |

| `--background-neutral-faded` | Pressed fill |
| `--outline-color-focus` | Focus ring |

## Do / Don't

- **Do** pass `aria-label` on every icon-only `ToggleButton`.
- **Do** use `manual` when something other than a click drives the state
  (selection, external data) — don't fight the self-toggle script.
- **Don't** use `ToggleButton` for navigation or single-fire actions — that's
  `Button`. A toggle must represent a persistent on/off state.
- **Don't** rely on color alone to show pressed — the fill + text-color pair
  already carries it; don't strip that via `class`.

## Content

- Icon-only: no visible label, `aria-label` names the action, not the state
  ("Bold", not "Toggle bold").
- With text: a short noun or verb naming the setting ("Bold", "Show grid"), not
  its state ("On"/"Off") — the pressed style already shows that.
