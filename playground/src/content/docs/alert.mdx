## Add

```sh
npx @ava-ui/apogee add alert
```

Uses `@lucide/astro` (`Info`, `CircleCheck`, `TriangleAlert`, `CircleAlert`) for the per-variant icon.

## Usage

```astro
---
import Alert from '@/components/apogee/Alert/Alert.astro'
---
<Alert variant="success" title="Saved">Your changes were saved.</Alert>
```

## API

`@composable` — exposed to Content Editors in AVA. Any other attribute (e.g.
`role`, `aria-live`, `id`) passes through.

| Prop | Type | Default | Description |
|---|---|---|---|
| `variant` | `'info' \| 'success' \| 'warning' \| 'danger'` | `'info'` | Status color + icon. |
| `title` | `string` | — | Optional bold heading above the message. |
| `class` | `string` | — | Extra classes, merged last. |

## States

Alert is static — no hover/focus/disabled states. The one behavioral distinction
is static (page) vs dynamic (result of an action), which changes the ARIA role
you pass in, not the markup:

<Preview code={`<Alert variant="warning" title="Limited availability">
  Only 2 left in stock.
</Alert>
<Alert variant="danger" title="Couldn't save" role="alert">
  Check the highlighted fields and try again.
</Alert>`}>
  <Alert variant="warning" title="Limited availability">
    Only 2 left in stock.
  </Alert>
  <Alert variant="danger" title="Couldn't save" role="alert">
    Check the highlighted fields and try again.
  </Alert>
</Preview>

```astro
</Alert>
```

## Accessibility

- Icons are `aria-hidden` — the status is conveyed by the adjacent text, not color/icon alone.
- Static, page-authored alerts need no role.
- A dynamically-shown alert (e.g. a form result) should get `role="alert"` (passed
  through via `...rest`) so assistive tech announces it on insertion.

## Tokens

| Token | Used for |
|---|---|
| `--accent` / `--accent` (10% bg, 25% border) | Info icon + surface |
| `--success` | Success icon + surface |
| `--warning` | Warning icon + surface |
| `--danger` | Danger icon + surface |
| `--foreground` | Title text |
| `--muted-foreground` | Body text (when a title is present) |

## Do / Don't

- **Do** match the variant to the message's actual severity — don't use `danger` for a neutral notice.
- **Do** keep the title short; put detail in the body.
- **Don't** stack more than one Alert for the same event — pick the highest-severity one.
- **Don't** use `danger` for destructive-action confirmation — that's a dialog's job, not an inline alert's.

## Content

- Title: 2–5 words, sentence case, no ending period, states the outcome ("Couldn't save", not "Error").
- Body: one or two short sentences. Say what happened and, for warnings/danger, what to do next.
