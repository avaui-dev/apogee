Color is the one token category that's runtime-overridable per theme — every
other scale (radius, spacing, motion, type) is static. Components never read
a raw palette step; they read a semantic role (`bg-accent`,
`text-muted-foreground`), so a theme is one attribute flip, not a rebuild.

## Semantic tokens

Neutral ramp is Tailwind zinc; accent is Tailwind blue as a placeholder —
swap either in `registry/tokens/theme.css`.

| Token | Light | Dark | Used for |
|---|---|---|---|
| `--background` | `white` | `zinc-950` | Page background |
| `--foreground` | `zinc-900` | `zinc-50` | Body text on background |
| `--surface` | `zinc-50` | `zinc-900` | Raised/panel background (cards, popovers) |
| `--surface-foreground` | `zinc-900` | `zinc-50` | Text on surface |
| `--muted` | `zinc-100` | `zinc-800` | Subtle fill (chips, code, hover rows) |
| `--muted-foreground` | `zinc-600` | `zinc-400` | De-emphasized text |
| `--border` | `zinc-200` | `zinc-800` | Dividers, outlines |
| `--accent` | `blue-600` | `blue-500` | Primary brand fill / links |
| `--accent-hover` | `blue-700` | `blue-400` | Accent hover state |
| `--accent-foreground` | `white` | `zinc-950` | Text/icon on accent fill |
| `--danger` | `red-600` | `red-500` | Destructive actions, errors |
| `--danger-hover` | `red-700` | `red-400` | Danger hover state |
| `--danger-foreground` | `white` | `zinc-950` | Text on danger fill |
| `--success` | `green-700` | `green-500` | Positive status |
| `--success-foreground` | `white` | `zinc-950` | Text on success fill |
| `--warning` | `amber-500` | `amber-400` | Caution status |
| `--warning-foreground` | `zinc-950` | `zinc-950` | Text on warning fill |
| `--ring` | `blue-600` | `blue-500` | Focus ring |

## Dark mode

Dark mode is a token override under `[data-theme="dark"]`, not a separate
stylesheet or component variant:

```css
:root,
[data-theme="light"] {
  --background: var(--color-white);
  --foreground: var(--color-zinc-900);
  --accent: var(--color-blue-600);
  --accent-foreground: var(--color-white);
}

[data-theme="dark"] {
  --background: var(--color-zinc-950);
  --foreground: var(--color-zinc-50);
  --accent: var(--color-blue-500);
  /* bright 500-level fill flips to dark text for AA — see below */
  --accent-foreground: var(--color-zinc-950);
}
```

Set `data-theme` on `<html>` (or any ancestor) and every component under it
repaints — no prop, no rebuild.

## The WCAG AA contrast gate

Every semantic pair that carries text — or a focus indicator — is required to
meet **WCAG 2.1 AA**: 4.5:1 for normal text, 3:1 for the focus ring. This
isn't a design guideline someone eyeballs; it's enforced by a script that
computes the real ratios and fails the build on a miss:

```sh
npm run check:contrast
```

`scripts/check-contrast.mjs` reads the semantic mapping straight out of
`registry/tokens/theme.css` and the ramp values from Tailwind's own theme
(OKLCH), converts each OKLCH color to sRGB, computes luminance, and derives
the WCAG contrast ratio for every pair, in both themes. No dependencies — the
color math is self-checked against black/white = 21:1 at the bottom of the
script.

| Pair | Role | Min | Light | Dark |
|---|---|---|---|---|
| `foreground` / `background` | body text | 4.5 | 17.7 | 19.1 |
| `foreground` / `surface` | text on surface | 4.5 | 17.0 | 17.0 |
| `muted-foreground` / `background` | muted text | 4.5 | 7.7 | 7.6 |
| `muted-foreground` / `muted` | muted text on fill | 4.5 | 7.0 | 5.7 |
| `accent` / `background` | link / accent text | 4.5 | 5.3 | 5.3 |
| `accent-foreground` / `accent` | text on accent fill | 4.5 | 5.3 | 5.3 |
| `danger-foreground` / `danger` | text on danger fill | 4.5 | 4.8 | 5.2 |
| `success-foreground` / `success` | text on success fill | 4.5 | 4.9 | 9.0 |
| `warning-foreground` / `warning` | text on warning fill | 4.5 | 9.3 | 11.6 |
| `ring` / `background` | focus ring | 3.0 | 5.3 | 5.3 |

### Bright dark-mode fills take a dark foreground

Dark mode's `accent`, `danger`, and `success` are bright 500-level colors (they
need to read against a near-black background), which flips their `-foreground`
to near-black `zinc-950` rather than white — the same trick `warning` already
uses in light mode. Two decisions this drove:

- `muted-foreground` is zinc-**600**, not 500, so muted text still clears AA
  even sitting on a `muted` fill (e.g. `Kbd`).
- `success` is green-**700** in light mode, not 600, so white text on a
  success fill passes.

If you want white text on a primary button in dark mode instead, swap in a
darker accent (`blue-600`) and re-run the gate — don't hand-pick a lighter
foreground and hope.

### What isn't gated

- **Decorative borders and dividers** are exempt under WCAG 1.4.11 — they
  don't identify a component, so `border` isn't tested.
- Pairs that never render as text-on-fill aren't asserted beyond the roles
  in the table above.

Run `check:contrast` after changing any color token — before it ships, not
after someone reports it.
