Every design decision in Apogee — colour, spacing, radius, motion, type — is a
CSS variable, not a hard-coded value in a component. Components read tokens;
they never own their own colours or sizes. This is what makes theming a
one-place edit instead of a find-and-replace across every component.

## Tokens are Tailwind `@theme` variables

Tailwind v4 has no config file — tokens are declared in CSS, inside a
`@theme` block, and Tailwind turns each one into both a real CSS custom
property and a matching utility class:

```css
@import "tailwindcss";

@theme {
  --radius-md: 0.5rem;
  --duration-base: 180ms;
}
```

`--radius-md` becomes the utility `rounded-md`. It's also inspectable and
overridable at runtime, in DevTools or in your own CSS — same variable, both
places.

## Semantic tokens sit on top of the palette

Colour works in two layers:

1. **The palette** — Tailwind's tuned ramp (`--color-zinc-900`,
   `--color-blue-600`, …), generated by Tailwind itself. You never reference
   these directly from a component.
2. **Semantic tokens** — a plain CSS variable per *role* (`--accent`,
   `--foreground`, `--danger`) that points at one palette step:

```css
--accent: var(--color-blue-600);
--foreground: var(--color-zinc-900);
```

A component uses `bg-accent`, `text-foreground` — the role, never the ramp
step. That's what lets a theme swap the entire palette (zinc → slate, blue →
purple) without touching a single component.

## The alias chain — and the real override point

Semantic tokens don't feed Tailwind's utilities directly. `registry/tokens/theme.css`
re-exposes each one through `@theme inline`, aliasing `--color-accent` back to
the semantic `--accent`:

```css
:root, [data-theme="light"] {
  --accent: var(--color-blue-600); /* 1. semantic token names a palette step */
}

@theme inline {
  --color-accent: var(--accent);   /* 2. Tailwind utility aliases the semantic token */
}
```

That gives `bg-accent` / `text-accent` / `border-accent` utilities that
resolve through `--color-accent` → `--accent` → the palette. **The override
point is `--accent`, not `--color-accent`.** Redeclaring `--color-accent`
directly works in isolated CSS but fights the alias and skips the
`[data-theme]` cascade every other token relies on — always override the
semantic variable.

## Token categories

| Category | Example tokens | Defined in |
|---|---|---|
| Color | `--background`, `--accent`, `--danger` (+ `-foreground`) | `:root` / `[data-theme="dark"]` (runtime) |
| Radius | `--radius-sm` … `--radius-xl` | `@theme` (static) |
| Spacing | `--spacing-gutter`, `--spacing-section` (+ `-sm`/`-lg`) | `@theme` (static, fluid) |
| Motion | `--duration-fast/base/slow`, `--ease-smooth`, `--ease-emphasized` | `@theme` (static) |
| Typography | `--text-display`, `--text-h1` … `--text-h6` | `@theme` (static, fluid) |

Color is the one category that's runtime-overridable per theme (see
[Color](/color)). Radius, spacing, motion and typography are static scales —
one value, no light/dark variant.

### Radius

| Token | Value |
|---|---|
| `--radius-sm` | `0.3rem` |
| `--radius-md` | `0.5rem` |
| `--radius-lg` | `0.75rem` |
| `--radius-xl` | `1rem` |

→ utilities `rounded-sm` … `rounded-xl`.

### Motion

| Token | Value | Use |
|---|---|---|
| `--duration-fast` | `120ms` | menus, hovers, small toggles |
| `--duration-base` | `180ms` | most transitions |
| `--duration-slow` | `260ms` | expanding regions, dialogs |
| `--ease-smooth` | `cubic-bezier(0.16, 1, 0.3, 1)` | enter / general |
| `--ease-emphasized` | `cubic-bezier(0.65, 0, 0.35, 1)` | in-out moves |

`ease-*` ship as utilities; durations stay CSS variables for scoped styles
(`transition: opacity var(--duration-base) var(--ease-smooth)`) and arbitrary
values (`duration-[var(--duration-fast)]`). Tailwind's own transition
defaults are wired to these tokens
(`--default-transition-duration: var(--duration-fast)`), so a bare
`transition-colors` is already on-brand. Always keep a
`prefers-reduced-motion` guard on anything animated.

### Typography

Fluid `clamp()` scale — `text-display`, `text-h1` … `text-h6`, each with a
paired line-height, interpolating between a small viewport (~320px) and a
large one (~1440px). No breakpoint jumps.

```css
--text-h1: clamp(2rem, 1.5rem + 2.5vw, 3rem);
--text-h1--line-height: 1.1;
```

### Spacing (fluid layout)

For page/section layout only — component internals keep Tailwind's fixed
numeric scale (`p-2`, `gap-4`).

| Utility | Token | Clamp |
|---|---|---|
| `px-gutter` | `--spacing-gutter` | `1rem` → `2rem` |
| `py-section-sm` | `--spacing-section-sm` | `2rem` → `3.5rem` |
| `py-section` | `--spacing-section` | `3rem` → `6rem` |
| `py-section-lg` | `--spacing-section-lg` | `4rem` → `9rem` |

`Container` uses `px-gutter` for its responsive side gutter.

## How to theme

A theme is a token override, cascaded under a `[data-theme]` attribute — not
a component prop or variant. Flip the attribute on `<html>` and every
component using semantic tokens repaints, automatically:

```css
:root,
[data-theme="light"] {
  --accent: var(--color-blue-600);
  --accent-hover: var(--color-blue-700);
  --accent-foreground: var(--color-white);
}

[data-theme="dark"] {
  --accent: var(--color-blue-500);
  --accent-hover: var(--color-blue-400);
  /* bright 500-level fill needs dark text for AA — see Color */
  --accent-foreground: var(--color-zinc-950);
}
```

To rebrand, swap the palette step each semantic token points at (or point it
at a raw value) — components never change:

```css
:root {
  --accent: oklch(55% 0.2 300); /* custom brand purple instead of blue-600 */
}
```

After editing any colour token, run `npm run check:contrast` — see
[Color](/color) for the AA gate this must pass.

## Not now

- No token editor UI or runtime theme picker — that's an AVA app concern, not
  this design system.
- No per-component token overrides (e.g. a `Button`-only accent) — theming is
  global, by design.
